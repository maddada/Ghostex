# Ghostex terms

What the words we use for Ghostex mean, so users, agents and code reviews stay on the same page. Add or update an entry whenever the user defines a new term or renames a concept.

- **Chief of Staff**: the Ghostex-wide coordinator, one agent session per computer, its chat a row pinned first in **Main Hub**. Users see "Chief of Staff" (2026-11-08: back from "Main Hub", which now names only the home project; it was "Chief of Staff" in Q1896 and shipped as "Chief" in 11.1.0, Q1746; working names were "master coordinator" and "head coordinator"). It holds the **head role** while its built-in extension is on: it may type into, interrupt and answer the prompts of any session without the owner's approval, and nothing more than an agent otherwise. New Chat keeps the old chat asleep in Main Hub as an _earlier chat_. Code says `chief` (`server/src/chief/`, `/api/chief`, `ghostex chief`, the `chiefHidden` setting) and `SessionRow::is_chief` / `SessionRole::Head`.
- **Main Hub** (the home project; a beta built-in extension, off by default, `mainHubHidden`, which also covers Chief of Staff): the project rooted at the computer's home folder (`~`, `C:\Users\<name>` on Windows), where sessions that belong to no project live, with Chief of Staff pinned first (user decisions Q1911 to Q1916, Q1993 and 2026-11-08). An existing project at that folder is adopted. With computers combined every computer's home is one Main Hub. Agents Ghostex starts there are kept out of the **secret folders** (`homeSecretFolders`). Code says `isHome` (`server/src/chief/home.rs`).
- **Coordinator**: the agent session the user talks to about a stream of work. It plans the work, hands it to threads, keeps track of them and reports back. Called Orchestrator from 2026-10-10 to 2026-10-28, when the user renamed it back to Coordinator everywhere in the app and made `ghostex coordinator …` the real command group; `ghostex orchestrator …` stays as an alias that runs the same commands (running agents and old briefs use it). The skill kept the name `ghostex-orchestrator` until 2026-11-11, when it was renamed `ghostex-coordinator` (`/ghostex-coordinator`) and installs moved over to the new name on their first start; some settings keys and JSON fields still say `orchestrator` (`orchestratorPlaybook`, `orchestratorPlainReplies`, `orchestratorAllEfforts`).
- **Coordinator playbook**: the `ghostex-coordinator` skill's text (named `ghostex-orchestrator` until 2026-11-11), how every coordinator works (the user first called it the "orchestrator prompt"). Ghostex ships one; the user can keep an edited copy for all projects (Settings > Chat) and for any project (Settings > Projects), where a project's copy also covers all of its worktrees, and a switch turns an edited copy off without losing it. `ghostex coordinator guide` prints the one in effect (the project's, else the all-projects one, else Ghostex's). It is separate from a coordinator's own _standing instructions_ (Goal & Instructions…). Replaced the short-lived default "Coordinator instructions" (2026-10-19). Code and API routes say `coordinatorPlaybooks` and `/api/*CoordinatorPlaybook`.
- **GBots**: Ghostex's own bots, led by Chief of Staff in Main Hub (user decision 2026-11-08: "we are doing our own bots thing"). A **GBot** (or a bot) is a lasting persona with a name, standing instructions and memory that every one of its chats shares; its chats are ordinary agent sessions on the user's own Claude Code or Codex. Turned on in Settings > Extensions (`gbotsEnabled`, needs Main Hub). A **department** groups GBots under a name with shared instructions every member follows and at most one **lead**, who hands its members work; departments exist only inside GBots (never a project, Space or folder). Code says `gbots` (`server/src/gbots/`, `/api/gbots`, `ghostex gbots …`). The previous GBots, a separate downloaded runtime shown in the Bots space, was removed in the same change; its bots were not carried over.
- **Secret request**: an agent asking the user for a password, API key or token through a private card above the chat box (`ghostex secret request`). The answer goes to an owner-only file the agent's commands read, deleted after 24 hours; it never enters the chat, the transcript or the model's context.
- **Secret provider**: a password manager Ghostex reads saved keys and tokens from instead of keeping them (Settings > Secrets). 1Password, through its `op` CLI, is the only kind so far; a setting or a secret request can be given a 1Password reference (`op://vault/item/field`) in place of the value.
- **Thread**: an agent session a coordinator starts and briefs to do one piece of work. It sits under its coordinator in the sidebar, and its final message is its report to the coordinator. The chat's pill that lists a coordinator's threads is called **Workers** (renamed from Threads 2026-10-28).
- **Issues Workflow**: starting work from a ticket (a branch, worktree and agent linked to it), Link to in a session's menu, the Issues view's ticket list, Create ticket, the primary tracker, titling sessions by their branch and the Clean up offer when a linked PR merges. There is no switch: it is on for every project once set up; its Linear parts show once a Linear API key applies to the project and its GitHub parts once `gh` is signed in (user decision 2026-10-24). Formerly **Work mode**, a per-project switch (renamed 2026-10-24); code, API routes, setting keys and saved data still say `workMode` / `work_mode`, and `ghostex work-mode …` still works as an alias of `ghostex issues …`. Branch titles and the Clean up offer are their own settings (`titleSessionsByBranch`, `offerCleanupWhenPrMerges`, Settings > Session Cards). The PR, issue and Linear chips on sessions are **session links**, which every project has.
- **Ticket source**: where a workspace's tickets come from: Linear, GitHub issues, or a **ticket command**, a program the user points a workspace at (`ghostex issues source set <path>`) that describes its own tracker through an `info --json` answer (its id, name, icon, ID format and the credentials it needs). The command and its credentials are set only on the computer that runs the workspace, never for a workspace connected to a team. In code it is a `WorkSource`; the command's own module is `server/src/work_mode/command/`.
- **Beads view**: the view panel's view of the project's Beads issues (the `bd` tracker), with a **Tree** layout (every bead under its epic, the default) and a **Board** layout (lanes by status). Formerly the **Kanban** view (renamed 2026-11-11); code, hotkeys and saved data still say `kanban` (`TitlebarMode::Kanban`, `switchKanbanView`, `kanbanViewTabHidden`, `native_kanban/` for the Board), and the Tree lives in `native_beads/`.
- **Needs a decision**: the Beads view's pinned group of beads waiting on a person, the ones bd flags with the `human` label (`bd human`); **Answer** replies to one (`bd human respond`, which comments and closes it).
- **Issues view**: the view panel's list of tickets and pull requests, opened from the briefcase at the top of the sidebar or Open a view. Formerly the Work view or Work page (renamed 2026-10-24); code and saved data still say `work` (`TitlebarMode::Work`, `apps/desktop/views/work/`).
- **Current session** (Issues view): the session selected in the window that hosts the Issues view. The ticket's Start chat ▾ menu offers **Link to current session**, which adds the ticket to that session's links.
- **Start in cloud**: starting a ticket's work as a Claude cloud session from the Issues view or `ghostex issues start <ticket> --cloud`, with a task Ghostex drafts from the ticket. The session gets the same sidebar row as any Claude cloud session, with the ticket's chip. The list of clouds it offers is the cloud runner's provider list (`server/src/cloud_runner.rs`).
- **Claude cloud session**: a Claude session that runs in Claude's cloud (Claude Code on the web, claude.ai/code) on one of the user's Claude accounts, and has an ordinary sidebar row (starting with the agent's orange cloud) under the project of the repo's main folder. Started with the **Claude (cloud)** agent, drawn as an orange cloud (New Thread's agent list, or `ghostex create-agent claude-cloud`). Clicking the row opens the session's claude.ai page in Ghostex's Browser; its status comes from that page and from its branch and pull request. Code and saved data say `claudeCloud` (`runtimeSettings.claudeCloud`, `runLocation: claude-cloud`).
- **Bring to This Computer**: a Claude cloud session's menu action that continues it on this computer: a local Claude session in a new worktree teleports it (`claude --teleport`), takes over, and the cloud row parks.
- **claude.ai in Ghostex**: the claude.ai sign-in of one saved Claude account, kept in that account's own Browser profile and used for its cloud sessions' pages and, since 2026-10-25, the Claude view while that account is picked in its account bar (Settings > Accounts shows it per Claude account, with Sign in to claude.ai and Sign out).
- **Claude** (built-in extension): claude.ai inside Ghostex, switched on in Settings > Extensions > Store (Features), off by default (user decision 2026-10-25: built in, not a Store extension). It adds the **Claude button** to the sidebar's top row, beside Issues, which turns Claude on: the **Claude view** takes the sessions column's place and the sidebar, the side panel and the Commands pane are hidden (user decision 2026-10-28); it is never a side panel tab, and the side panel still opens beside it. Showing the sidebar (Toggle sidebar or Cmd+B) turns it off and goes back to the Space, project, session and layout from before it (user decision 2026-10-29: Claude is like its own Space and project); the left-edge peek leaves it on. The same button, or opening any session (a sidebar click, Quick Access, a notification, a new agent, a hotkey, the phone or CLI), also turns it off and brings the layout back. Code and saved data say `claudeWeb` (`claudeWebHidden`, the `claude-web` view id, `apps/desktop/src/app/claude_web/`).
- **Account bar** (Claude view): the slim bar above the Claude page: the saved Claude account the page is signed in with (signed-in dot, name, email), a menu to switch accounts, sign out of claude.ai or manage accounts, and Reload. The pick is saved in `claude-web-account.json`.
- **Marked handovers**: agents beginning each section of the message they hand back to the user with a marker; threads always do it, and the Settings > Chat option Marked handovers (`markedHandovers`: Off, Coordinators only by default, or Every session) decides whether coordinators do (all but Off) and whether every other agent session Ghostex starts does too (Every session) (❓ Needs you, ✅ Done, ⚠️ Read this, 🛫 Kicked off, 🔄 In progress, 🧪 Untested, 🚀 Shipped, 🛑 Blocked). A _handover_ is that final message of a turn; a thread's report to its coordinator is one too. The chat colours those _marked sections_ by kind, in the style set by `markedHandoversStyle` (coloured labels, thin left rule or coloured badge).
- **Handoff to an agent / Handoff to MD**: the two cards at the top of Handoff / Export (user decision 2026-10-31). Handoff to an agent starts the follow-up session, in this project on the same computer by default; its _destination_ row's Change… opens the Computer and Project choices for another project or another connected computer, in every direction (this computer to a remote, a remote back, remote to remote), with the conversation's Markdown file linked in the new chat box (carried over when it changes computer). Handoff to MD only saves the file (called Export to Markdown before). The dialog remembers the card, the agent, the destination and Include (`ghostex_gx_core::handoff_prefs`); the saved mode `handoffRemote` of older versions loads as Handoff to an agent with the destination choices open.
- **History** (Handoff / Export): inside Include, how much of the conversation the file holds (user decision 2026-11-03, Q1150 to Q1159): a **Whole conversation** switch and, while it is off, a slider over the last 1, 2, 3, 5, 10, 20, 50 or 100 _turns_, starting at 20. A turn is the user's message and everything up to their next one; the file lists the user's messages from the older turns at its top. Remembered with the other choices (`ghostex_gx_core::handoff_prefs`); gxserver cuts the file (`lastTurns` on `/api/exportSessionTranscript`) and counts it for the dialog's estimate (`/api/countSessionTranscriptTurns`, `ghostex count-transcript-turns`).
- **Ghostex terminal config**: the Ghostty-syntax config file Ghostex's own terminals load (`config.ghostty` in the `ghostty` folder of Ghostex's config folder: `~/.config/ghostex/ghostty/` on macOS and Linux, `%APPDATA%\Ghostex\ghostty\` on Windows), separate from the **Ghostty config**, the Ghostty app's own file, which Ghostex never reads for its terminals or writes (user decision 2026-10-14). Settings > Terminal writes its rows into the Ghostex terminal config; **Import from Ghostty** copies fonts, line height and cursor settings (never the theme) from the Ghostty config into it.
- **Theme preset** (Settings > Interface > Presets): one of the twenty theme cards (Catppuccin Mocha, Dracula, Nord and the like) that sets the colour, Colourfulness, terminal palette and terminal background settings in one step so Ghostex looks like that theme. Nothing records which one was picked. Not the same as the **colour squares** (Graphite, Slate, …) under Colours, whose settings keys are still named `darkThemePreset` / `lightThemePreset`; a theme preset sets those keys to `custom`.
- **Auto-switch** (Settings > Accounts): whether Ghostex may move a session to this account when another account hits its limit, shown as an Auto-switch on or off tag. Formerly labelled Automatic / Manual and "Available for automatic switching" (renamed 2026-10-14); code and saved data still say `eligible`.
- **Session badge** (Settings > Accounts, under Advanced): the up to two letters or numbers drawn over a session's agent icon to tell its account apart. Formerly the Account indicator (renamed 2026-10-14); code and saved data still say `indicator`.
- **Account number** (Settings > Accounts, under Advanced): the number Claude Swap or Codex Swap gives a saved login (`cswap run 2`), swappable with another account's. Formerly shown as a slot ("Swap slot N with", renamed 2026-10-14); code and saved data still say `selector` and slot.
- **Rules** (Settings > Accounts): a provider's settings for every account of it, opened from Claude rules or Codex rules in the account list: New sessions start on, When an account hits its limit (Switch accounts, Wait for reset, Do nothing), Try first, retries and saved resets. Formerly New session defaults (renamed 2026-10-14); code and saved data still say `defaults`, `newSessionAccounts` and `policy`.
- **Disabled account** (Settings > Accounts, the Enabled switch): an account the user turned off. It stays saved but out of use: never picked for new sessions or switches, not polled for usage or sign-in, hidden from switch menus and the sidebar usage; sessions already on it keep running. Not the same as **Subscription access disabled**, which gxserver sets on its own after Claude refuses an account. Code and saved data say `userDisabled` / `user_disabled`; the API operation is `setEnabled`.
- **5h / 7d**: the only names for usage windows anywhere in Ghostex (user decision 2026-10-14): the five-hour window is `5h`, the weekly one `7d`, a model's weekly window `<Model> 7d` (the compact Fable label stays `Fable`). Never "weekly" or "five-hour".
- **Files tab** (Quick Access): the fifth Quick Access tab (Cmd+O opens it, Cmd+5 switches to it while Quick Access is open), which searches the files of every sidebar project, the current project first, and opens the picked file where Settings > File opening says. Not the same as the **Files view**, the view panel's file browser and editor (`native_docs/`), which is where a picked file opens by default. Code and saved data say `files` / `quickAccessFiles`; gxserver answers it with `/api/searchProjectFiles`.
- **Store** (Settings > Extensions > Store): the Settings page with every extension as a card, the built-in feature switches and the extension store, first in the rail's collapsible **Extensions** group (Store, Workspaces, Cloud Boxes, Connectors, Actions, Open In, OS Integration, Debugging). Formerly the Extensions page (renamed 2026-10-19); its page id and saved data still say `extensions`. Not the same as the header ⋯ menu's **Extensions** entry, which lists the installed extensions.
- **Side chat**: a fork of a session that answers beside it in the same folder, started with the chat box's Side Chat pill or `/btw <question>` (user decision 2026-11-02, replacing the agent CLI's own `/btw`). It is not a session in the sidebar: the main chat's **Side chats** pill lists it, it opens as a tab in the side panel (its own chat screen on the phone), and Bring back sends what it said to the main session. Code and saved data say `sideChat` (`sideChatParentSessionId`, `/api/startSideChat`, server/src/side_chats/).
- **Session details panel**: the panel beside a Claude chat (beta built-in extension, Settings > Extensions > Store) that shows where the session runs, its context use with Claude's own breakdown, its task list, connectors, skills, memory files, changes and background commands; opened from the context ring in the window's header, docked beside the chat when there is room and floating otherwise. Not the **view panel** (Code, Browser, Files). Code and saved data say `sessionDetails` (`sessionDetailsPanelHidden`, `/api/readSessionDetails`).
- **Copy Report** (chat): the button on a chat's "Message not sent" card (the agent's input box is not on screen) that copies a Markdown report of what Ghostex sees in that session (the whole terminal screen as gxserver captures it, the input-box verdict, the terminal's size and clients, the queue, recent send problems, the Ghostex version and OS), shows a toast saying it can be pasted and sent, and opens Send Bug / Feedback with "Collect more data with an agent" on (user decision 2026-10-25). gxserver writes it (`/api/readSessionChatReport`, `server/src/session_chat_report.rs`); the chat core's action is `copyReport`.
- **Ghostex page** (short **gx page**): an HTML page an agent publishes with `ghostex show`, which the chat shows as a card that opens it (where Settings > Chat > Open Ghostex pages in says); it may ask questions and send the answers back. Formerly "inline HTML", "chat page" or "question page" (renamed by the user 2026-11-06); agents still understand the old words. Code says `page`, `PageRef`, `visual_pages`, `gx-page`, and the setting key is `chatPageOpenTarget`.
- **Ghostex form** (short **gx form**): questions an agent asks as a form in the chat, a ```questions block, and the one-click answers for a quick pick. Formerly "inline questions", "inline q" or "question form" (renamed 2026-11-06). Code says `questions`, `QuestionForm`, `form`.
- **Ghostex visuals** (short **gx visuals**): charts, graphs, stat tiles and tables an agent draws in the chat with a ```visual block. Formerly "inline graphs" or "charts" (renamed 2026-11-06). Code says `visual`, `gx-visual`, `chart`.
- **For later**: a Ghostex form, or a Ghostex page that asks questions, in a chat that the user put off to answer another time (user's words, 2026-10-27). It stays answerable but no longer counts as unanswered: no pink dot, no count on the chat's ? pill, no notification. **Back to unanswered** undoes it, and answering it ends it. gxserver keeps the list per session (`runtimeSettings.sessionChatQuestionsForLater`, sent to chats as `laterQuestionIds`).
- **Chat Resources** (the questions list): the list the chat's Resources pill opens: the chat's generated content (Ghostex forms, Ghostex pages with or without questions, and Ghostex visuals), filtered by All, Pages, Forms or Visuals (Html, Q&A and Charts until 2026-11-06), in two groups, Unanswered and Earlier. Code says `openQuestions.sections` and `filters`, with filter ids `html`, `qa` and `charts`.
- **Copy Link** (`https://ghostex.dev/open/session#<Global Ref>`, which opens `ghostex://session/<Global Ref>`): the link to one session, from a session's Copy submenu. Opening it from outside Ghostex brings the app forward and focuses that session, on this computer or a connected machine, and asks first when that would start its agent or restore it from Previous Sessions. Not the same as **session links**, the PR, issue and Linear chips on a session.
- **View** (a chat's More actions > View): the chat's one view, **Summary**, **Normal** or **Detailed**, picked per chat; turning Summary off always goes to Normal, and Settings > Chat > Advanced > Default to Detailed view (`sessionChatDetailedView`) makes new chats start Detailed (user decision 2026-11-02). Normal was called **Simple mode** before (renamed 2026-11-02) and **Verbose** was a fourth level, retired the same day (a chat saved on it opens Detailed). Code and saved data still say `simple`, `verbose` and `summary` for the per-chat records, and `viewLevel` for the resolved choice; the composer's chip for it is the **view chip**.
- **Cloud Box**: a Linux machine on the user's own Instabox or Boat account that runs a Ghostex session, with Ghostex's server on the box (user decisions 2026-11-02). Picked with the Cloud Box choice in a new chat; Settings > Cloud Boxes connects providers, sets the monthly cap and lists every box. The older agentbox boxes (Docker, your SSH server, Hetzner, Vercel, Daytona, E2B, DigitalOcean) are **More providers** under that page's Advanced. Code says `cloud_boxes`, `cloudBox` and `/api/cloudBoxes`; a debug-only `local` provider runs a box as a Docker container for development.
- **Default snapshot** (★): the snapshot of a project a new Cloud Box starts from (Settings > Projects > Cloud box). **Update** saves a running box of the project as the new Default and keeps the old one as **Previous** for 7 days.
- **Box chip**: the pill in a Cloud Box session's header with the box's state, running time and about-$ cost; its menu stops, deletes and snapshots the box.
- **Box picker**: the menu the chip beside a new chat's Cloud Box segment opens: a snapshot or a Blank box for a new box, a running box to reuse, the provider and size, and the agentbox places under **More providers**. Code: `packages/gx-chat-core/src/menus/cloud_box.rs`.
- **Boot card**: the progress lines a Cloud Box chat's first message waits with (checking the cap, starting the box, starting Ghostex on it, logins and secrets, fetching the code and starting the agent, connecting). Code: the tray's `status.card`.
- **Box token**: the one-year `claude setup-token` value a Claude account gets when it is allowed on Cloud Boxes (Settings > Cloud Boxes > Agent logins for boxes). It never rotates, so the computer's own Claude login is never signed out by a box.
- **Cloud kit**: what "Start boxes from your phone" (`cloudBoxesPhoneStartEnabled`) keeps on paired phones so they can start a Cloud Box while the computer is off: a provider key, agent logins for boxes, Default snapshots and the picked secrets.
- **Work area frame**: the optional look that shows the work area (everything right of the sidebar) as one card inside the window, with a thin margin all around, a hairline border and a light shadow, the way Arc frames its pages (Settings > Interface > Advanced > Frame the work area, with its row "Show the window buttons when the sidebar is collapsed" under it, on by default for a new install and kept off for an existing settings file, macOS only). The margin round the card is the _gutter_. Code: `workAreaFrame`, `apps/desktop/src/app/helpers/work_area_frame.rs`.
- **Active projects**: the star tile first in the sidebar's Space row (user decision 2026-11-12), a Space-like view that lists, flat and in Space order, every project from every Space and connected computer that has a session working or waiting on the user, or was used in the last 8 hours. On by default (`sidebarActiveProjects`, Settings > Sidebar & Sessions > Spaces); the star's right-click menu removes it. Code calls its selection the reserved Space id `active` (gx-core `sidebar_view/active_projects.rs`). Not the "active Space", which is whichever Space or view is selected.
- **Settings sync**: keeping chosen settings the same on the user's own computers whenever two of them are connected to each other (a Remote machine, Easy Connect or Tailscale), peer to peer with no server (user decisions Q1370 to Q1378, 2026-11-06). Settings > Sync picks what syncs (Sidebar organization on by default; Appearance, Agent defaults, Agents, Skills, Accounts, Sounds and notifications, Keybindings and Coordinator off), one switch set per computer. **Sidebar organization** (the switch `syncSpaces`, called Spaces before 2026-11-12) is the Spaces, their order and projects, project groups, the sidebar settings that arrange the sidebar and the custom Session Tags; code keys it `spaces/`. The **sync group** is the computers that sync with each other: every computer connected to one of them joins, and one removed on any of them stops syncing. A **sync note** ("Changed on X · Undo") tells the computer whose change lost that another computer's later change to the same thing won. Code says `settings_sync` (gx-core `settings_sync`, `server/src/settings_sync/`), routes `/api/settingsSyncExchange` and `/api/*SettingsSync*`.
- **Ghostex Collab**: sharing a chat with someone through a link that opens it in their browser, no app or account needed (user decisions 2026-11-07, Q1610 to Q1617: "we need a page in settings called "Collab" and we need to call this feature Ghostex Collab"). An extension: since 11.0.1 (GitHub #495) the app ships none of its code, and the owner installs it in Settings > Extensions (signed approval), which downloads the **Collab component** (`ghostex-collab`, a sidecar gxserver runs); uninstalling removes it. a chat's **Share** button in its header makes the link (`share.ghostex.dev/s/<page id>/#<key>`), its eight-digit **code** (always asked) and its expiry (an hour by default, a day at most). Installing Collab, sharing, Send mode and approving a guest's message each need the owner's signed approval (Touch ID or the system's equivalent), and the **pinned guest page** is the exact page this release trusts: gxserver checks the relay serves it before sharing through it. The person who opens it is a **guest**: they see that one chat live, pick a name, and write in it; in **Approve each message** (the default) their message waits as a "Message from <guest>" card the owner answers with Decline, Edit or Send, and the other modes are Straight to the agent (Send) and View only. The **share relay** is Ghostex's server that carries the link's traffic, locked end to end so it can't read it. Code says `collab` (`server/collab/` the component, `server/src/collab_shim/` gxserver's side, `/api/collab`, `extras::collab`).
- **Command pad** (iPhone terminal): the movable nine-key pad opened with the four-square button, with arrows, Enter, Esc, Ctrl+C, Tab and Upload to start. Upload asks for Photo Library or Choose File, as the terminal menu's Send & Attach File does. Settings > Keyboard > Pad keys changes the keys; holding and dragging its button moves it to either side, with its own position for laptop mode.
- **Pad layers** (iPhone command pad): Keys and Agent hotkeys, opened from the buttons around the pad in the keyboard's place. Keys holds Extra keys and More keys; Agent hotkeys holds the session agent's terminal shortcuts and is dimmed, with a tap showing why, when the agent has none. Their editors are in Settings > Keyboard.
- **Text editor** (iPhone command pad): the pen's multiline draft above the keyboard. Its up-arrow inserts text into the terminal without Enter; with no text its send button sends Enter. It is not a file editor.
- **Project file browser** (the phone's Files): the read-only folder tree of the whole project, with search, file-type filters, previews, Copy Full Path and Share…. Add to Session Context, when opened from an agent session, puts a file's text in that session's input without sending it. Not the desktop's editable Files view.
- **Laptop mode** (iPhone Duo): half folded like a laptop, with terminal output, the chat view and the text editor above the fold, and the keyboard or a pad layer below it. Lists such as Sessions, Files and Licences run on below the fold, while most Settings pages end above it. The command pad has a separate saved position in this pose.
- **Panes** (iPhone Duo): two areas on the inner display, stacked upright or side by side across and in laptop mode, opened with the session header's Panes button, which brings back the pane types and divider stored for that arrangement (a pane that showed another session opens New pane instead) or, with none, opens New pane. Closing applies to every arrangement and keeps each one's panes for the next Panes. At least one stays a session; the other can show a session, Web Preview, Files, Git Changes, Agents, Usage or Attention. Only one shows Chat at a time, and a chat in a pane has a compact chat box.
- **Session wall** (iPhone Duo): the Sessions list shown as tiles on the inner display, picked with Show as tiles and changed back with Show as list. A tile adds status words and the latest terminal lines to the session's name and agent; folded and on other phones the list stays in use.
- **Folded triage** (iPhone Duo, Waiting for you): the waiting-session cards above the Sessions list on the outer display, longest wait first, with approval and single-choice answers, Open Question for other questions, and Short replies for other waits. The list's filter and search apply to these cards too.
- **Short Replies** (the phone's Settings > Short Replies): the editable texts offered on the folded triage's other waiting cards. Tapping one sends it to that card's session immediately, not to a draft.
- **Actions…** (phone): the project's menu of Project Actions followed by its computer's Global Actions when available. In the Unified list it is in a session's long-press menu and uses that session's computer and project.
- **Live Activity** (iPhone): the Lock Screen card and Dynamic Island counts of working and waiting agents, controlled in Settings > Live Activity. It starts while Ghostex is open, can show older content marked Not current, and is separate from a notification alert.
- **Demo computer** (phone): a sample machine named Demo computer, opened with **Try a demo computer** on the first screen, or from Connect your computer via the card of that name and **Open demo**. Its projects (Atlas API, Side project, Wander), sessions, chat, terminal and Web Preview are bundled with the app and kept in memory. It never pairs, never signs in, and never uses the network. Voice is off. Remove it from Settings > Demo computer > Remove demo computer. Pairing a real computer is separate. App Review uses this demo.
- **Home Screen widget** (iPhone): the Ghostex widget in small, medium or large size (small in StandBy), showing working and waiting agents as of the app's saved update. Updated says when the data was read; it is not a continuously connected view.
- **Theme preset** (phone, Settings > Interface > Presets): a one-time choice of app colours, colourfulness, terminal palette and terminal background together. Individual controls can be changed afterwards; the matching card is selected only while its settings still match.
- **Terminal palette** (phone): the terminal's text and colour set for dark or light mode, chosen separately in Settings > Interface. Import Ghostty theme adds a private palette from a local theme file without choosing it or importing an app theme or other Ghostty settings; Terminal background is a separate control in Settings > Terminal.
- **Licences** (the phone's Settings > Licences): the searchable list of third-party components bundled with the iPhone app, with versions and licences; tapping a component opens its licence texts. It does not need a connection to the computer and is separate from the desktop's notices.
- **Advisor shared notes** (OMP chat on the phone): the foldable card of advisor notes, with counts by severity in its closed row and severity labels beside the notes when opened.
- **Fast Computer & Browser use**: what first-run setup's Workspace panel calls Computer Use (the Cua Driver helper and the Computer Use skill that let agents see the screen and drive apps and web pages outside Ghostex). The user named it on 2026-11-11 when it moved there from the Agents panel; Settings > Integrations and the code still say Computer Use (`cuaDriver`, `computerUseSkill`).
