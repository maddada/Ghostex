# Ghostex terms

What the words we use for Ghostex mean, so users, agents and code reviews stay on the same page. Add or update an entry whenever the user defines a new term or renames a concept.

- **Coordinator**: the agent session the user talks to about a stream of work. It plans the work, hands it to threads, keeps track of them and reports back. Called Orchestrator from 2026-10-10 to 2026-10-28, when the user renamed it back to Coordinator everywhere in the app and made `ghostex coordinator …` the real command group; `ghostex orchestrator …` stays as an alias that runs the same commands (running agents and old briefs use it). The skill is still named `ghostex-orchestrator`, and some settings keys and JSON fields still say `orchestrator` (`orchestratorPlaybook`, `orchestratorPlainReplies`, `orchestratorAllEfforts`).
- **Coordinator playbook**: the `ghostex-orchestrator` skill's text, how every coordinator works (the user first called it the "orchestrator prompt"). Ghostex ships one; the user can keep an edited copy for all projects (Settings > Chat) and for any project (Settings > Projects), where a project's copy also covers all of its worktrees, and a switch turns an edited copy off without losing it. `ghostex coordinator guide` prints the one in effect (the project's, else the all-projects one, else Ghostex's). It is separate from a coordinator's own _standing instructions_ (Goal & Instructions…). Replaced the short-lived default "Coordinator instructions" (2026-10-19). Code and API routes say `coordinatorPlaybooks` and `/api/*CoordinatorPlaybook`.
- **Secret request**: an agent asking the user for a password, API key or token through a private card above the chat box (`ghostex secret request`). The answer goes to an owner-only file the agent's commands read, deleted after 24 hours; it never enters the chat, the transcript or the model's context.
- **Secret provider**: a password manager Ghostex reads saved keys and tokens from instead of keeping them (Settings > Secrets). 1Password, through its `op` CLI, is the only kind so far; a setting or a secret request can be given a 1Password reference (`op://vault/item/field`) in place of the value.
- **Thread**: an agent session a coordinator starts and briefs to do one piece of work. It sits under its coordinator in the sidebar, and its final message is its report to the coordinator. The chat's pill that lists a coordinator's threads is called **Workers** (renamed from Threads 2026-10-28).
- **Issues Workflow**: starting work from a ticket (a branch, worktree and agent linked to it), Link to in a session's menu, the Issues view's ticket list, Create ticket, the primary tracker, titling sessions by their branch and the Clean up offer when a linked PR merges. There is no switch: it is on for every project once set up; its Linear parts show once a Linear API key applies to the project and its GitHub parts once `gh` is signed in (user decision 2026-10-24). Formerly **Work mode**, a per-project switch (renamed 2026-10-24); code, API routes, setting keys and saved data still say `workMode` / `work_mode`, and `ghostex work-mode …` still works as an alias of `ghostex issues …`. Branch titles and the Clean up offer are their own settings (`titleSessionsByBranch`, `offerCleanupWhenPrMerges`, Settings > Session Cards). The PR, issue and Linear chips on sessions are **session links**, which every project has.
- **Ticket source**: where a workspace's tickets come from: Linear, GitHub issues, or a **ticket command**, a program the user points a workspace at (`ghostex issues source set <path>`) that describes its own tracker through an `info --json` answer (its id, name, icon, ID format and the credentials it needs). The command and its credentials are set only on the computer that runs the workspace, never for a workspace connected to a team. In code it is a `WorkSource`; the command's own module is `server/src/work_mode/command/`.
- **Issues view**: the view panel's list of tickets and pull requests, opened from the briefcase at the top of the sidebar or Open a view. Formerly the Work view or Work page (renamed 2026-10-24); code and saved data still say `work` (`TitlebarMode::Work`, `apps/desktop/views/work/`).
- **Current session** (Issues view): the session selected in the window that hosts the Issues view. The ticket's Start chat ▾ menu offers **Link to current session**, which adds the ticket to that session's links.
- **Start in cloud**: starting a ticket's work as a Claude cloud session from the Issues view or `ghostex issues start <ticket> --cloud`, with a task Ghostex drafts from the ticket. The session gets the same sidebar row as any Claude cloud session, with the ticket's chip. The list of clouds it offers is the cloud runner's provider list (`server/src/cloud_runner.rs`).
- **Claude cloud session**: a Claude session that runs in Claude's cloud (Claude Code on the web, claude.ai/code) on one of the user's Claude accounts, and has an ordinary sidebar row (starting with the agent's orange cloud) under the project of the repo's main folder. Started with the **Claude (cloud)** agent, drawn as an orange cloud (New Thread's agent list, or `ghostex create-agent claude-cloud`). Clicking the row opens the session's claude.ai page in Ghostex's Browser; its status comes from that page and from its branch and pull request. Code and saved data say `claudeCloud` (`runtimeSettings.claudeCloud`, `runLocation: claude-cloud`).
- **Bring to This Computer**: a Claude cloud session's menu action that continues it on this computer: a local Claude session in a new worktree teleports it (`claude --teleport`), takes over, and the cloud row parks.
- **claude.ai in Ghostex**: the claude.ai sign-in of one saved Claude account, kept in that account's own Browser profile and used for its cloud sessions' pages and, since 2026-10-25, the Claude view while that account is picked in its account bar (Settings > Accounts shows it per Claude account, with Sign in to claude.ai and Sign out).
- **Claude** (built-in extension): claude.ai inside Ghostex, switched on in Settings > Extensions > Store (Features), off by default (user decision 2026-10-25: built in, not a Store extension). It adds the **Claude button** to the sidebar's top row, beside Issues, which turns Claude on: the **Claude view** takes the sessions column's place and the sidebar, the side panel and the Commands pane are hidden (user decision 2026-10-28); it is never a side panel tab, and the side panel still opens beside it. Showing the sidebar (Toggle sidebar or Cmd+B) turns it off and goes back to the Space, project, session and layout from before it (user decision 2026-10-29: Claude is like its own Space and project); the left-edge peek leaves it on. The same button, or opening any session (a sidebar click, Quick Access, a notification, a new agent, a hotkey, the phone or CLI), also turns it off and brings the layout back. Code and saved data say `claudeWeb` (`claudeWebHidden`, the `claude-web` view id, `apps/desktop/src/app/claude_web/`).
- **Account bar** (Claude view): the slim bar above the Claude page: the saved Claude account the page is signed in with (signed-in dot, name, email), a menu to switch accounts, sign out of claude.ai or manage accounts, and Reload. The pick is saved in `claude-web-account.json`.
- **Marked handovers**: agents beginning each section of the message they hand back to the user with a marker; coordinators and their threads always do it, and the Settings > Chat option Marked handovers in every session (`markedHandovers`, off by default) extends it to every other agent session Ghostex starts (❓ Needs you, ✅ Done, ⚠️ Read this, 🛫 Kicked off, 🔄 In progress, 🧪 Untested, 🚀 Shipped, 🛑 Blocked). A _handover_ is that final message of a turn; a thread's report to its coordinator is one too. The chat colours those _marked sections_ by kind, in the style set by `markedHandoversStyle` (coloured labels, thin left rule or coloured badge).
- **Handoff to an agent / Handoff to MD**: the two cards at the top of Handoff / Export (user decision 2026-10-31). Handoff to an agent starts the follow-up session, in this project on the same computer by default; its _destination_ row's Change… opens the Computer and Project choices for another project or another connected computer, in every direction (this computer to a remote, a remote back, remote to remote), with the conversation's Markdown file linked in the new chat box (carried over when it changes computer). Handoff to MD only saves the file (called Export to Markdown before). The dialog remembers the card, the agent, the destination and Include (`ghostex_gx_core::handoff_prefs`); the saved mode `handoffRemote` of older versions loads as Handoff to an agent with the destination choices open.
- **Ghostex terminal config**: the Ghostty-syntax config file Ghostex's own terminals load (`config.ghostty` in the `ghostty` folder of Ghostex's config folder: `~/.config/ghostex/ghostty/` on macOS and Linux, `%APPDATA%\Ghostex\ghostty\` on Windows), separate from the **Ghostty config**, the Ghostty app's own file, which Ghostex never reads for its terminals or writes (user decision 2026-10-14). Settings > Terminal writes its rows into the Ghostex terminal config; **Import from Ghostty** copies fonts, line height and cursor settings (never the theme) from the Ghostty config into it.
- **Auto-switch** (Settings > Accounts): whether Ghostex may move a session to this account when another account hits its limit, shown as an Auto-switch on or off tag. Formerly labelled Automatic / Manual and "Available for automatic switching" (renamed 2026-10-14); code and saved data still say `eligible`.
- **Session badge** (Settings > Accounts, under Advanced): the up to two letters or numbers drawn over a session's agent icon to tell its account apart. Formerly the Account indicator (renamed 2026-10-14); code and saved data still say `indicator`.
- **Account number** (Settings > Accounts, under Advanced): the number Claude Swap or Codex Swap gives a saved login (`cswap run 2`), swappable with another account's. Formerly shown as a slot ("Swap slot N with", renamed 2026-10-14); code and saved data still say `selector` and slot.
- **Rules** (Settings > Accounts): a provider's settings for every account of it, opened from Claude rules or Codex rules in the account list: New sessions start on, When an account hits its limit (Switch accounts, Wait for reset, Do nothing), Try first, retries and saved resets. Formerly New session defaults (renamed 2026-10-14); code and saved data still say `defaults`, `newSessionAccounts` and `policy`.
- **Disabled account** (Settings > Accounts, the Enabled switch): an account the user turned off. It stays saved but out of use: never picked for new sessions or switches, not polled for usage or sign-in, hidden from switch menus and the sidebar usage; sessions already on it keep running. Not the same as **Subscription access disabled**, which gxserver sets on its own after Claude refuses an account. Code and saved data say `userDisabled` / `user_disabled`; the API operation is `setEnabled`.
- **5h / 7d**: the only names for usage windows anywhere in Ghostex (user decision 2026-10-14): the five-hour window is `5h`, the weekly one `7d`, a model's weekly window `<Model> 7d` (the compact Fable label stays `Fable`). Never "weekly" or "five-hour".
- **Files tab** (Quick Access): the fifth Quick Access tab (Cmd+O opens it, Cmd+5 switches to it while Quick Access is open), which searches the files of every sidebar project, the current project first, and opens the picked file where Settings > File opening says. Not the same as the **Files view**, the view panel's file browser and editor (`native_docs/`), which is where a picked file opens by default. Code and saved data say `files` / `quickAccessFiles`; gxserver answers it with `/api/searchProjectFiles`.
- **Store** (Settings > Extensions > Store): the Settings page with every extension as a card, the built-in feature switches and the extension store, first in the rail's collapsible **Extensions** group (Store, Workspaces, Cloud Boxes, Connectors, Actions, Open In, OS Integration, Debugging). Formerly the Extensions page (renamed 2026-10-19); its page id and saved data still say `extensions`. Not the same as the header ⋯ menu's **Extensions** entry, which lists the installed extensions.
- **Side chat**: a fork of a session that answers beside it in the same folder, started with the chat box's Side Chat pill or `/btw <question>` (user decision 2026-11-02, replacing the agent CLI's own `/btw`). It is not a session in the sidebar: the main chat's **Side chats** pill lists it, it opens as a tab in the side panel (its own chat screen on the phone), and Bring back sends what it said to the main session. Code and saved data say `sideChat` (`sideChatParentSessionId`, `/api/startSideChat`, server/src/side_chats/).
- **Session details panel**: the panel beside a Claude chat (beta built-in extension, Settings > Extensions > Store) that shows where the session runs, its context use with Claude's own breakdown, its task list, connectors, skills, memory files, changes and background commands; opened from the context ring in the window's header, docked beside the chat when there is room and floating otherwise. Not the **view panel** (Code, Browser, Files). Code and saved data say `sessionDetails` (`sessionDetailsPanelHidden`, `/api/readSessionDetails`).
- **Copy Report** (chat): the button on a chat's "Message not sent" card (the agent's input box is not on screen) that copies a Markdown report of what Ghostex sees in that session (the whole terminal screen as gxserver captures it, the input-box verdict, the terminal's size and clients, the queue, recent send problems, the Ghostex version and OS), shows a toast saying it can be pasted and sent, and opens Send Bug / Feedback with "Collect more data with an agent" on (user decision 2026-10-25). gxserver writes it (`/api/readSessionChatReport`, `server/src/session_chat_report.rs`); the chat core's action is `copyReport`.
- **For later**: a question form or question page in a chat that the user put off to answer another time (user's words, 2026-10-27). It stays answerable but no longer counts as unanswered: no pink dot, no count on the chat's ? pill, no notification. **Back to unanswered** undoes it, and answering it ends it. gxserver keeps the list per session (`runtimeSettings.sessionChatQuestionsForLater`, sent to chats as `laterQuestionIds`).
- **Chat Resources** (the questions list): the list the chat's ? pill opens (hover on the computer, tap on the phone): the chat's generated content (question forms, HTML pages with or without questions, and charts), filtered by All, Html, Q&A or Charts, with questions in Unanswered, For later, Answered and Withdrawn sections and the rest under Pages and Charts, newest first. Code says `openQuestions.sections` and `filters`.
- **Copy Link** (`https://ghostex.dev/open/session#<Global Ref>`, which opens `ghostex://session/<Global Ref>`): the link to one session, from a session's Copy submenu. Opening it from outside Ghostex brings the app forward and focuses that session, on this computer or a connected machine, and asks first when that would start its agent or restore it from Previous Sessions. Not the same as **session links**, the PR, issue and Linear chips on a session.
- **View** (a chat's More actions > View): the chat's one view, **Summary**, **Normal** or **Detailed**, picked per chat; turning Summary off always goes to Normal, and Settings > Chat > Advanced > Default to Detailed view (`sessionChatDetailedView`) makes new chats start Detailed (user decision 2026-11-02). Normal was called **Simple mode** before (renamed 2026-11-02) and **Verbose** was a fourth level, retired the same day (a chat saved on it opens Detailed). Code and saved data still say `simple`, `verbose` and `summary` for the per-chat records, and `viewLevel` for the resolved choice; the composer's chip for it is the **view chip**.
- **Cloud Box**: a Linux machine on the user's own Instabox or Boat account that runs a Ghostex session, with Ghostex's server on the box (user decisions 2026-11-02). Picked with the Cloud Box choice in a new chat; Settings > Cloud Boxes connects providers, sets the monthly cap and lists every box. The older agentbox boxes (Docker, your SSH server, Hetzner, Vercel, Daytona, E2B, DigitalOcean) are **More providers** under that page's Advanced. Code says `cloud_boxes`, `cloudBox` and `/api/cloudBoxes`; a debug-only `local` provider runs a box as a Docker container for development.
- **Default snapshot** (★): the snapshot of a project a new Cloud Box starts from (Settings > Projects > Cloud box). **Update** saves a running box of the project as the new Default and keeps the old one as **Previous** for 7 days.
- **Box chip**: the pill in a Cloud Box session's header with the box's state, running time and about-$ cost; its menu stops, deletes and snapshots the box.
- **Box picker**: the menu the chip beside a new chat's Cloud Box segment opens: a snapshot or a Blank box for a new box, a running box to reuse, the provider and size, and the agentbox places under **More providers**. Code: `packages/gx-chat-core/src/menus/cloud_box.rs`.
- **Boot card**: the progress lines a Cloud Box chat's first message waits with (checking the cap, starting the box, starting Ghostex on it, logins and secrets, fetching the code and starting the agent, connecting). Code: the tray's `status.card`.
- **Box token**: the one-year `claude setup-token` value a Claude account gets when it is allowed on Cloud Boxes (Settings > Cloud Boxes > Agent logins for boxes). It never rotates, so the computer's own Claude login is never signed out by a box.
- **Cloud kit**: what "Start boxes from your phone" (`cloudBoxesPhoneStartEnabled`) keeps on paired phones so they can start a Cloud Box while the computer is off: a provider key, agent logins for boxes, Default snapshots and the picked secrets.
