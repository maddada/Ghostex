# Ghostex settings reference

Generated by `packages/settings-catalog` from the Settings catalog. Do not edit by hand; run `cargo xtask help-generate`.

How to use this file:

- Every row is a Settings control. The backtick word is the settings key used by `ghostex settings get|set|reset <key>`.
- `ghostex settings list --json` prints the same catalog with the current values, so prefer it over reading this file when the app is available.
- Rows marked `not agent-writable`, `structured value`, or `Settings UI row` must be changed by the user in Settings. Open the right page with `ghostex settings open <key>`.
- The desktop app must be running for `set`; it applies the change exactly like a save in the Settings modal.

## Chat (tab `chat`)

### Chat

- **Default view for compatible agents** `preferredAgentInterface` (one of terminal | chat; default chat): Automatically switch to chat as soon as Ghostex detects that an agent session supports it. Option labels: terminal = Terminal, chat = Chat.
- **Close empty sessions when starting a new one** `closeEmptySessionsOnNew` (boolean, default false) [advanced]: When you start a new session, close this project's other sessions that have nothing typed, drafted or queued. Only applies when Chat is the default view for that agent; with Terminal it never runs.
- **Custom transcript width (set with Transcript width)** `sessionChatCustomTranscriptWidthEnabled` (boolean, default false) [advanced]: On once Transcript width is dragged to a percentage; off keeps Auto, where the transcript matches the prompt composer's width.
- **Transcript width** `sessionChatTranscriptWidthPercent` (number 50 to 100 step 5 default 75) [advanced]: The centered transcript's width on wide panes. Auto matches the prompt composer; drag to set a percentage of the pane instead. The prompt composer keeps its standard width either way.
- **Show file edit previews** `sessionChatFileEditPreviews` (boolean, default false): Show the first seven code lines in each file edit. Turn off to show only the path and change counts.
- **Tool call cards (preview)** `chatToolCallCards` (boolean, default false): Show each run of tool calls as one card: it counts the calls, says what each one is doing and then did, with its result and time, explains a failure, and folds to one line once the agent writes again. Off keeps the current look.
- **Default to Detailed view** `sessionChatDetailedView` (boolean, default false) [advanced]: New chats open in Detailed view, with the work under each agent reply shown. Off, they open in Normal view. More actions > View in a chat picks Summary, Normal or Detailed for that chat.
- **Keep chat box expanded while scrolling** `sessionChatKeepComposerExpanded` (boolean, default false) [advanced]: Keep the desktop chat box at full size while you scroll the transcript instead of shrinking it as you scroll up and growing it back at the end.
- **Press Escape twice to interrupt** `sessionChatConfirmEscapeInterrupt` (boolean, default true) [advanced]: While the agent is working, the first Escape asks you to press Escape again within 2 seconds before it interrupts. Turn off to interrupt on the first Escape.
- **Catch me up button** `chatCatchMeUp` (boolean, default false): Show a Catch me up button at the top right of the chat box while it is empty. It has your Title Generation Agent (a small, cheap model) read the session's last 30 agent messages and shows where the session stands: what needs you, what is done, in progress or untested.
- **Send when you pick an answer** `chatSendOnPick` (boolean, default false) [advanced]: When a question card asks one question, picking an answer sends it right away, without Send answers. Cards with several questions, multiple-choice questions, Other and text answers still wait for Send.
- **Wait for turn end before sending form answers** `chatAnswersWaitForIdle` (boolean, default false) [advanced]: Send answers from question forms and chat pages only after the agent finishes its turn. Off sends them like a normal chat message, which the agent can read after its current tool call finishes.
- **Open chat pages in** `chatPageOpenTarget` (one of popup | files | system-browser; default popup): Where a page an agent shows in chat (a mockup, a question form, a comparison) opens when you click its card: a popup over the chat, the Files view, or your default web browser. Answers you send from the page reach the agent the same way in all three. The phone always opens pages in its own viewer. Option labels: popup = Popup, files = Files, system-browser = System browser.
- **Coordinator board opens as** `coordinatorBoardView` (one of list | columns; default list): What the Board pill above a coordinator's chat box opens: its lines of work as a list beside the chat, or as columns over the chat, one per group. The switch at the top of either view changes this too. Option labels: list = Side list, columns = Columns.
- **Tell agents about Ghostex** `agentGhostexNote` (boolean, default true): Agent sessions Ghostex starts get a short note that they run in Ghostex: it can show pages, questions and charts in the chat, install Ghostex skills, and `ghostex agent-guide` explains the rest. Agents use it only when you ask for one of those things. Applies to sessions started or resumed after you change it.
- **Every effort level in coordinator pickers** `orchestratorAllEfforts` (boolean, default false) [advanced]: Also lists the levels above XHigh (Max, Ultra and the like) in the coordinator effort pickers, where the agent has them. Coordinators work best on High or XHigh.
- **Coordinator playbook** `orchestratorPlaybook` (Settings UI row without a settings key; use `ghostex settings open`) [advanced]: How every coordinator works: the playbook it follows. Edit it for all projects here, or for one project and its worktrees in Settings > Projects. Coordinators, existing ones too, follow the edited playbook from their next guide read, and a switch turns an edited playbook off without losing it.
- **Read aloud voice** `readAloudVoice` (text: the id of a voice installed on this computer (on a Mac, for example `com.apple.voice.compact.en-US.Samantha`), easiest picked on its Settings row; default (empty), the system voice): The voice Read aloud speaks the agent's replies with: System voice, or one of the voices installed on this computer. Add voices in your computer's speech or accessibility settings. The phone has its own Voice in its Settings > Chat. Only on macOS.
- **Read aloud speed** `readAloudRate` (number one of 0.75 | 1 | 1.25 | 1.5 | 2; default 1): How fast Read aloud speaks, from 0.75× to twice as fast. Ghostex in a browser uses it too; the phone has its own Speed. Option labels: 0.75 = 0.75×, 1 = 1×, 1.25 = 1.25×, 1.5 = 1.5×, 2 = 2×.
- **Read aloud** `readAloudUnavailable` (Settings UI row without a settings key; use `ghostex settings open`): Read aloud can't speak on this computer, so it has no controls here. It works in the Ghostex phone app and in Ghostex in a browser connected to this computer. Only on Windows and Linux.
- **Claude task list** `sessionDetailsClaudeTaskTools` (boolean, default true): Turn on Claude's task list tools, so Claude can keep a checklist that the Session details panel shows. Recent Claude models only get them when Ghostex asks. Applies to Claude sessions started or woken after you change it. Shown while the Session details panel extension is on.
### Marked handovers

- **Marked handovers in every session** `markedHandovers` (boolean, default false): Coordinators and their threads start each part of the message they hand back with a marker such as ✅ Done or 🧪 Untested, and end it with what needs you (⚠️ Read this, 🛑 Blocked, 💡 Suggestions, ❓ Needs you), so you never miss it. Turn this on to have every other agent session do the same. Applies to sessions started or resumed after you change it.
- **Show marker emojis** `markedHandoversEmoji` (boolean, default false) [advanced]: Not recommended. Show the marker emoji (❓ ✅ ⚠️ and the rest) at the start of each coloured section, in every style. Off: the colour and the label show the kind. Shown while Marked handovers is on.
- **Marked sections style** `markedHandoversStyle` (one of labels | rule | badge; default labels) [advanced]: How the chat colours the sections an agent marks: coloured labels, a thin left rule, or a coloured badge in place of the emoji. Shown while Marked handovers is on. Option labels: labels = Coloured labels, rule = Thin left rule, badge = Coloured badge.
- **Heading colour strength** `markedHandoversHeadingStrength` (number 0 to 100 step 10 default 60) [advanced]: How strongly the coloured section headings in agents' handovers (Done, Needs you, Untested and the rest) stand out. 100% is full colour; lower values blend the headings toward the normal text colour, and 0% leaves them in plain bold text.
- **Coordinators answer without markers** `orchestratorPlainReplies` (boolean, default false) [advanced]: Not recommended. Coordinators answer normally, without marking the sections of their handovers. Their threads still mark the reports they send to the coordinator. Applies to coordinators started or resumed after you change it.
## Sidebar & Sessions (tab `sidebar`)

### Sidebar

- **Preset** `sidebarSettingsPreset` (Settings UI row without a settings key; use `ghostex settings open`): Apply a sidebar UI preset or show Custom when controlled settings diverge.
- **Sidebar** `sidebarView` (one of project | unified; default project): Project sidebar lists each project with its sessions under it. Unified sidebar shows every session in one list, with the ones that need you on top. Both show every connected computer together unless Separate by machine is on. Option labels: project = Project sidebar, unified = Unified sidebar.
- **Separate by machine** `sidebarSeparateByMachine` (boolean, default false): Show one computer at a time, each with its own tab, project list and Spaces. Off (the default): one list for every connected computer, where a project on several computers is one entry with the sessions of all of them, and Spaces and project groups are shared by all of them.
- **Working section** `unifiedWorkingSection` (boolean, default true): Fold sessions whose agent is working or still running something in the background into a Working section at the bottom of the list. They return to the top of the list when they need you. Shown while the Unified sidebar is selected.
- **Group by project** `unifiedGroupByProject` (boolean, default false): Put every machine's sessions of one repository under one header, with its Working, Snoozed and Parked sections inside it. Drag the headers to arrange them. Drafts stay above the groups. Also in the sidebar's Sort & Filter menu. Shown while the Unified sidebar is selected.
- **When switching to a Space** `sidebarSpaceSwitchBehavior` (one of restore | keep; default restore): Reopen the session you last had open in a Space when you switch to it, in the view its project was in. Shown while the Spaces extension is on. Option labels: restore = Restore the Space's projects, keep = Don't switch projects.
- **Switch Space when opening a session from another Space** `sidebarSpaceFollowActiveSession` (boolean, default false) [advanced]: Switch the selected Space to the one that owns a session you open from outside it, such as through Back/Forward or Search by Prompt. Shown while the Spaces extension is on.
- **Keep the last project running for** `projectSwitchKeepAliveMinutes` (number 0 to 60 default 10) [advanced]: After you switch to another project or Space, keep the terminals, chats, and view that were open in the previous project running for this many minutes so switching back is instant. 0 releases them right away. Keep views loaded (Auto Sleep) keeps every side panel view until its Auto Sleep time instead.
- **Remember sidebar per view** `sidebarVisibilityMemory` (one of shared | perView; default shared) [advanced]: Off: hiding the sidebar hides it everywhere. On: Agents and the wide views (Browser, Code, Files, Kanban, Automate) each keep their own open or hidden sidebar; the Commands pane follows the same split. Option labels: shared = Same in every view, perView = Remembered per view.
- **Card details: project icons** `showProjectIcons` (boolean, default true) [advanced]: Show project artwork or a square with the project’s first letter beside project names.
- **Card details: agent icon** `hideSessionAgentIconUntilHover` (boolean, default false) [advanced]: Hide session agent icons until a session row is hovered.
- **Card details: browser favicon** `hideBrowserFaviconUntilHover` (boolean, default false) [advanced]: Hide browser page favicons until a session row is hovered.
- **Card details: last active time** `hideLastActiveTimeOnSessionCards` (boolean, default true) [advanced]: Hide Last Active timestamps from session-card title rows.
- **Highlight unanswered questions** `highlightPendingQuestions` (boolean, default false) [advanced]: Give sessions with a detected unanswered question a soft pink background, including while the agent keeps working. Currently supports Codex asynchronous questions.
- **Card details: project git stats** `hideProjectHeaderDiffStats` (boolean, default false) [advanced]: Hide +added/-removed line counts in sidebar project rows.
- **Card details: changed-file count** `showProjectEditorDiffFileCount` (boolean, default false) [advanced]: Show changed-file counts in sidebar project row git stats.
- **Card details: untracked lines** `showUntrackedProjectDiffWhenNoTrackedChanges` (boolean, default false) [advanced]: Count untracked lines in a project's git stats when the tracked diff is +0 -0 (prompts like Starship ignore untracked lines).
- **Animations (fold speed, set with Animations)** `sidebarCollapseAnimationDurationMs` (number 0 to 1000 step 100 default 400) [advanced]: Set how quickly sidebar sections, groups, and projects expand or collapse, and how quickly the floating sidebar and Agents Panel slide in from the window edge. Set to 0 for no animation.
- **Animations** `panelAnimationSpeed` (one of off | slow | normal | fast; default normal) [advanced]: Set how fast the sidebar, the side panel, the Agents Panel and the bottom or right panel slide open and closed: Off, Slow, Normal or Fast. Reduce Motion in your computer settings always turns it off. Option labels: off = Off, slow = Slow, normal = Normal, fast = Fast.
- **Close side panel with its last tab** `closeSidePanelWithLastTab` (boolean, default true) [advanced]: Close the side panel when you close its last tab, instead of showing the Open a view picker.
- **Session tooltips delay (set with Session tooltips)** `sidebarTooltipDelayMs` (number 0 to 2000 step 100 default 600) [advanced]: Set how long sidebar hover labels wait before appearing. Set to 0 to show them immediately.
- **Sidebar width on double-click** `sidebarDefaultWidthPx` (number 150 to 520 default 275) [advanced]: Width restored when double-clicking the sidebar resize handle.
- **Commands pane height on double-click** `commandsPanelDefaultHeightPx` (number 40 to 600 default 125) [advanced]: Height used when opening the command pane and when double-clicking its top resize rail.
- **Commands pane side** `commandsPanelSide` (one of bottom | right; default bottom): Dock the command pane below the workspace or to its right. Option labels: bottom = Bottom, right = Right.
- **Auto-minimize Commands pane** `commandsPanelAutoMinimize` (boolean, default true) [advanced]: Minimize the Commands pane this long after you move focus elsewhere and the pointer leaves it. Commands keep running. Off keeps the pane open.
- **Minimize after (set with Auto-minimize Commands pane)** `commandsPanelAutoMinimizeDelaySeconds` (number one of 15 | 30 | 60 | 120 | 300; default 60) [advanced]: How long the Commands pane stays open after focus and the pointer leave it. Option labels: 15 = 15 seconds, 30 = 30 seconds, 60 = 1 minute, 120 = 2 minutes, 300 = 5 minutes.
- **Hide projects without sessions** `sidebarHideProjectsWithoutSessions` (boolean, default false): Leave projects with no sessions out of the Project sidebar, whatever state a session is in; the open project always stays, and a Show all projects row at the end of the list brings them back. Also in the sidebar's Sort & Filter menu.
- **Group working sessions** `groupWorkingSessions` (boolean, default false): Move sessions into a collapsed Working section under their project while their agent works; they return to Sessions when it stops or needs you. Also in the sidebar's Sort & Filter menu.
- **Double-click empty sidebar space to create a session** `createSessionOnSidebarDoubleClick` (boolean, default false) [advanced]: Create a session from empty sidebar space.
- **Enable session parking** `enableSessionParking` (boolean, default true): Move deferred sessions into a collapsible Parked section at the bottom of the sidebar.
- **Sleep session when parking** `sleepSessionWhenParking` (boolean, default false): Sleep a session automatically when it is moved into the Parked section.
- **Ask for a tag when parking or snoozing** `showTagMenuWhenParking` (boolean, default true): Open the Tag as menu when a session is parked or snoozed so it can be tagged right away.
- **Unpark after sending a message** `unparkAfterSendingMessage` (boolean, default true): Move a parked session out of the Parked section when you send it a message.
- **Double-click session cards to rename** `renameSessionOnDoubleClick` (boolean, default false) [advanced]: Makes clicking on a session respond a bit slower so we can detect the double click
### Session Cards

- **Session hover buttons (click to toggle, drag to reorder)** `sessionCardHoverButtons` (structured value; change it in Settings, not with `ghostex settings set`) [advanced]: Buttons a session card shows when you hover it in the Project sidebar. Click an icon to turn it on or off; drag icons to reorder them. Buttons to the right of the chevron always show, buttons to its left hide until the chevron is clicked. By default the strip is Tag, Park, Sleep, chevron, Close. The button beside the strip copies the Unified sidebar's. Shown while the Project sidebar is selected.
- **Session hover buttons (click to toggle, drag to reorder)** `unifiedSessionCardHoverButtons` (structured value; change it in Settings, not with `ghostex settings set`) [advanced]: Buttons a session card shows when you hover it in the Unified sidebar, which keeps its own strip. Click an icon to turn it on or off; drag icons to reorder them. Buttons to the right of the chevron always show, buttons to its left hide until the chevron is clicked, and opening the chevron opens it on every card. By default the strip is Tag, Sleep, chevron, Snooze, Park, Close. The button beside the strip copies the Project sidebar's. Shown while the Unified sidebar is selected.
- **Session links in the sidebar** `sidebarSessionLinks` (one of always | selected | badge | open | off; default badge): How a session card shows the pull requests, issues and Linear tickets it is linked to. Always: a line of them under every card that has any. Selected session: that line only under the session you have open. Badge: a small count on the card, coloured by the most pressing one, grey once all are merged or closed. Open work only: a line of the ones still open, none once they are all merged or closed. Hovering a card with links shows them all in a card beside the sidebar, except with Off, which shows nothing. Option labels: always = Always, selected = Selected session, badge = Badge, open = Open work only, off = Off.
- **Title sessions by their branch** `titleSessionsByBranch` (boolean, default false): Name a session after the branch it works on, without your name and the ticket number (yahia/spx-1245-copy-link shows as copy-link), until you rename it yourself. Sessions on main keep their own title.
- **Offer Clean up when a PR merges** `offerCleanupWhenPrMerges` (boolean, default true): When a session's pull request is merged, its card asks once whether to clean up (remove the session's worktree and park the session; a worktree with uncommitted changes is kept) or keep it.
- **Hover buttons also in context menu** `showSessionCardHoverButtonsInContextMenu` (boolean, default true) [advanced]: Also list the enabled hover buttons in the session right-click menu, in their usual place in the menu. Close is never listed while it is on the card. Turn off to leave every button out of the menu once it is on the card.
- **Session tooltips** `showSidebarSessionTooltips` (boolean, default true) [advanced]: Show a tooltip with the full session name when you hover a session in the sidebar. Turn off to show none; other sidebar tooltips stay.
### Sidebar Tags

- **Tag filter list** `sidebarSessionTagListItems` (structured value; change it in Settings, not with `ghostex settings set`): Add your own tags, then reorder, hide, disable, or delete tags and their separators for the sidebar and the Tag as menu.
### Sleeping Sessions

- **Dim sleeping sessions** `dimSleepingSessions` (boolean, default false) [advanced]: Fade sleeping sessions in the sidebar so they stand apart from awake ones.
- **Wake sleeping sessions when selected** `wakeSleepingSessionsOnSelect` (boolean, default true) [advanced]: Wake a sleeping session as soon as you select it. Turn off to open it with a Resume button instead, so switching sessions does not wake it by accident.
## Terminal (tab `terminal`)

### Terminal

- **Ghostty settings actions** `ghosttySettingsActions` (Settings UI row without a settings key; use `ghostex settings open`) [advanced]: Recommended terminal settings, Import from Ghostty (fonts and cursor, not the theme), the Ghostty app's config, Ghostex's own terminal config, Ghostty docs, and defaults.
- **Terminal background** `terminalBackgroundMode` (one of pure | theme | custom; default pure): Only changes the terminal panes. Black / white is pure black in dark mode and pure white in light mode. Option labels: pure = Black / white, theme = Follow theme, custom = Custom color.
- **Terminal background color** `workspaceBackgroundColor` (text, default (empty)): Custom terminal background, painted behind terminal text in dark mode.
- **Background opacity (%)** `terminalBackgroundOpacity` (number default 100) [advanced]: How much of the work area's glass tint terminals keep while transparency is on (Settings > Interface > Transparency). 100% matches the rest of the work area; lower shows more of what is behind the window. Off while transparency is off.
- **Background image** `terminalBackgroundImage` (text, default (empty)) [advanced]: Absolute path to an image drawn behind terminal panes.
- **Background image opacity** `terminalBackgroundImageOpacity` (number default 1) [advanced]: Blend the background image toward the terminal background color.
- **Font weight** `terminalFontWeight` (number default 300) [advanced]: Set terminal text weight.
- **Bold text uses a heavier font** `terminalBoldUsesHeavierFont` (boolean, default true) [advanced]: Draw bold terminal text in a heavier weight. Turn off to keep bold text at your normal font weight, so it stands out by color only. A font-style-bold or font-variation-bold line in Ghostex's terminal config takes priority.
- **Line height** `terminalLineHeight` (number default 1.2) [advanced]: Adjust terminal row height.
- **Letter spacing** `terminalLetterSpacing` (number default 0) [advanced]: Adjust spacing between glyphs.
- **Match chat width** `terminalViewWidthMode` (one of full | match-chat | custom; default full) [advanced]: Use the full pane, match the chat transcript, or set an independent terminal width. Option labels: full = Full, match-chat = Match Chat, custom = Custom.
- **Terminal width (%)** `terminalViewWidthPercent` (number 50 to 100 step 5 default 75) [advanced]: Set the centered terminal body width as a percentage.
- **Use this width in the Commands pane too** `terminalWidthApplyToCommandPaneTerminals` (boolean, default false) [advanced]: Apply the narrower terminal width to command pane terminals too.
- **Padding** `terminalPaneHorizontalPaddingPx` (number 0 to 64 default 0) [advanced]: Add left and right inner padding inside the terminal content area.
- **Vertical padding (set with Padding)** `terminalPaneVerticalPaddingPx` (number 0 to 64 default 0) [advanced]: Add top and bottom inner padding inside the terminal content area.
- **Cursor style** `terminalCursorStyle` (one of bar | block | underline; default bar): Choose the cursor shape. Option labels: bar = Line, block = Block, underline = Underline.
- **Cursor blink** `terminalCursorStyleBlink` (boolean, default true) [advanced]: Blink the terminal cursor.
- **Keep sleeping tabs asleep until clicked** `clickToWakeSleepingSessions` (boolean, default true) [advanced]: Select sleeping pane tabs without waking them until the empty pane is clicked.
- **Model picker in terminal view** `showQuickModelPickerInTerminal` (boolean, default true): Show a model button in the terminal bar and open the model picker with its shortcut (⌥P by default) in agent terminal sessions. Turn off to use terminal bindings.
- **Show session id in terminal panes** `showSessionIdInTerminalPanes` (boolean, default false) [advanced]: Show the provider session id in the top-right corner of terminal panes.
- **Editor for ⌃G and $EDITOR prompts** `promptEditorBackend` (one of monaco | inherit; default monaco) [advanced]: Choose which editor ⌃G uses when a terminal prompt asks for $EDITOR. Option labels: monaco = Ghostex editor, inherit = Use default from this machine.
- **Custom shaders (experimental)** `terminalShadersEnabled` (boolean, default false) [advanced]: Apply the shaders from Ghostex's terminal config in order. macOS with Metal only; tested on Apple Silicon. Intel Mac rendering is not yet validated. Windows and Linux are unsupported. Turn off to restore ordinary rendering in the same sessions.
- **Windows Environment** `windowsTerminalBackend` (one of powershell | wsl; default powershell): Windows only. PowerShell (default) runs native Windows projects and agents. WSL runs Linux projects. Changing environments prompts you to restart Ghostex. Option labels: powershell = PowerShell (Native), wsl = WSL (Linux).
- **WSL distribution** `windowsWslDistribution` (text, default (empty)): Windows only. Exact distro name from `wsl.exe --list --verbose`; blank uses automatic WSL2 discovery.
### Terminal Behavior

- **Scrollback limit** `terminalScrollbackLimitMb` (number default 15) [advanced]: Set scrollback memory per terminal surface.
- **Copy on select** `terminalCopyOnSelect` (one of false | true | clipboard; default false) [advanced]: Copy selected terminal text automatically. On macOS both options also copy to the system clipboard. Option labels: false = Off, true = Copy to clipboard, clipboard = System and selection clipboard.
- **Confirm close** `terminalConfirmCloseSurface` (one of true | always | false; default true) [advanced]: Confirm before closing terminal surfaces. Option labels: true = Smart confirmation, always = Always confirm, false = Do not confirm.
- **Trim trailing spaces on copy** `terminalClipboardTrimTrailingSpaces` (boolean, default true) [advanced]: Trim trailing whitespace when copying terminal text.
- **Paste protection** `terminalClipboardPasteProtection` (boolean, default true) [advanced]: Ask before pasting text Ghostty considers unsafe.
- **Paste images as preview links** `terminalPastePreviewableImages` (boolean, default true) [advanced]: Paste clipboard images as previewable Markdown links with ⌘V. Hold ⌘ over the linked path to preview it in the terminal, and see the same image preview in the ⌃G Rich Prompt Editor.
- **Hide mouse while typing** `terminalMouseHideWhileTyping` (boolean, default false) [advanced]: Hide the pointer while typing in the terminal.
- **Scrollbar** `terminalScrollbar` (one of system | never; default system) [advanced]: Control whether Ghostty shows its native scrollback scrollbar. Option labels: system = System, never = Never.
### Terminal Scrolling

- **Trackpad scroll speed** `terminalMouseScrollMultiplierPrecision` (number default 1) [advanced]: Trackpads and high-resolution scroll wheels. Ghostty default is 1.
- **Mouse wheel scroll speed** `terminalMouseScrollMultiplierDiscrete` (number default 1) [advanced]: Traditional notched mouse wheels. Ghostty default is 3.
- **Scroll to bottom when typing** `terminalScrollToBottomWhenTyping` (boolean, default true) [advanced]: Keep the prompt visible while typing.

## Updates (tab `updates`)

### Updates

- **Update all** `updatesUpdateAll` (Settings UI row without a settings key; use `ghostex settings open`): Updates everything listed that has an update: the agents you use, Claude Swap and Codex Swap, Fast Computer & Browser Use, SpaceO, the tools Ghostex installed, extensions, remote machines, the VS Code view and the Chromium runtime. Ghostex itself updates last and restarts once; your agents keep running, and each agent whose CLI changed restarts into the same chat once it finishes its turn.
- **Update automatically** `updatesAutoUpdate` (Settings UI row without a settings key; use `ghostex settings open`): A switch on each card, off by default: Ghostex installs that item's updates by itself, only while it isn't in use (an agent while none of its sessions is working, the other tools while no agent is working). On Ghostex's own card it is Keep this machine up to date.
- **Check now** `updatesCheckNow` (Settings UI row without a settings key; use `ghostex settings open`): Checks every item for a newer version now instead of waiting for the next check (every half hour).
### Up to date

- **Up to date** `updatesUpToDate` (Settings UI row without a settings key; use `ghostex settings open`): Everything already current, and the agents Ghostex can't read the version of (such as Cursor), with a button that runs their own updater.

### Stopping and deleting

- **Stop idle boxes after** `cloudBoxesIdleStopMinutes` (number 1 to 1440 step 1 one of 5 | 10 | 15 | 30 | 60 | 120; default 15): A box with no agent working and no terminal open pauses (Instabox) or stops (Boat) after this long. - **Delete archived boxes after** `cloudBoxesDeleteStoppedAfterDays` (number 1 to 365 step 1 one of 1 | 3 | 7 | 14 | 30; default 7): When every session on a box is archived, the box stops and is deleted after this many days. ## Remote (tab `remote`)

### Easy Connect

- **Easy Connect** `easyConnectEnabled` (Settings UI row without a settings key; use `ghostex settings open`): Connect a phone or a remote machine. Install the Tailcat CLI helper with one click.
- **SSH access** `sshAccess` (Settings UI row without a settings key; use `ghostex settings open`): Easy Connect carries SSH to this computer; Ghostex can turn it on with one admin prompt.
- **Pairing code** `pairingCode` (Settings UI row without a settings key; use `ghostex settings open`): Connect a Phone with a QR, or Connect a Remote machine with Copy Easy Connect code and its SSH username and password.
- **Paired devices** `pairedDevices` (Settings UI row without a settings key; use `ghostex settings open`): Phones and computers paired with this computer; remove one to unpair it and revoke its access.
- **Only paired devices can connect** `pairedDevicesOnly` (Settings UI row without a settings key; use `ghostex settings open`): Easy Connect lets in only paired phones and the keys listed under Advanced; a new phone can still pair while the QR is showing.
### Tailscale

- **Tailscale on or off** `tailscaleEnabled` (Settings UI row without a settings key; use `ghostex settings open`): Offer the Tailscale path; off keeps its card collapsed and hides it from Remote Setup.
- **Tailscale checklist** `tailscaleSteps` (Settings UI row without a settings key; use `ghostex settings open`): Reach this computer over your tailnet: Tailscale running, SSH access on, the app on your phone.
- **Tailscale code** `tailscaleCode` (Settings UI row without a settings key; use `ghostex settings open`): Scan the Tailscale code with the Ghostex app, or type the host, IP and username.
- **Tailscale on or off** `remoteTailscaleEnabled` (boolean, default true) [not agent-writable]: Offer the Tailscale path in Remote setup.
### Remote machines

- **Add a machine** `addMachine` (Settings UI row without a settings key; use `ghostex settings open`): Add a computer by SSH details or an Easy Connect code; saved machines appear as sidebar sections.
- **Show in sidebar** `showInSidebar` (Settings UI row without a settings key; use `ghostex settings open`): Hide a saved remote machine from the sidebar without deleting it.
- **Short names** `shortName` (Settings UI row without a settings key; use `ghostex settings open`): Each computer's 2-character name on the sidebar's computer pills, this one's included.
- **SSH host** `sshHost` (Settings UI row without a settings key; use `ghostex settings open`): Remote machine SSH host.
- **SSH user** `sshUser` (Settings UI row without a settings key; use `ghostex settings open`): Remote machine SSH user.
- **SSH port** `sshPort` (Settings UI row without a settings key; use `ghostex settings open`): Remote machine SSH port.
- **Identity file** `identityFile` (Settings UI row without a settings key; use `ghostex settings open`): SSH identity file used to connect to the remote machine.
- **Password** `password` (Settings UI row without a settings key; use `ghostex settings open`): SSH passwords are stored in the system keychain.
- **Install / Connect gxserver** `installGxserver` (Settings UI row without a settings key; use `ghostex settings open`): Install, update, or connect gxserver on a saved remote machine.
- **This computer's short name** `localMachineShortName` (text, default (empty)) [not agent-writable]: Up to 2 characters on the sidebar's computer pills; empty uses one made from the computer's name.
### Advanced

- **Easy Connect served ports** `servedPorts` (Settings UI row without a settings key; use `ghostex settings open`): Local ports Easy Connect exposes to paired phones.
- **Allowed client keys** `allowedClientKeys` (Settings UI row without a settings key; use `ghostex settings open`): Client keys allowed to connect; empty allows any device that scanned the code.
- **Pairing address** `pairingAddress` (Settings UI row without a settings key; use `ghostex settings open`): The raw Easy Connect address inside the QR, for pasting by hand.
- **Easy Connect binary** `binary` (Settings UI row without a settings key; use `ghostex settings open`): Path and version of the Easy Connect binary.
- **gxserver** `gxserver` (Settings UI row without a settings key; use `ghostex settings open`): Local API the app and phones talk to.
- **Raw Easy Connect status** `rawStatus` (Settings UI row without a settings key; use `ghostex settings open`): Raw Easy Connect status JSON for bug reports.
## Sync (tab `sync`)

### What syncs

- **Spaces** `syncSpaces` (boolean, default true): Keep Spaces and project groups the same on your computers while they are connected to each other: their names, icons, colours, order and which projects are in them. On by default.
- **Appearance** `syncAppearance` (boolean, default false): Keep the theme, colours, fonts, the chat's look and the glass the same on your computers. The glass picture or video, the interface scale and zoom stay on each computer. Off by default.
- **Agent defaults** `syncAgentDefaults` (boolean, default false): Keep the default agent, how new sessions open, the title agent, Accept all, and each agent's default model and effort the same on your computers. Off by default.
- **Sounds and notifications** `syncSoundsAndNotifications` (boolean, default false): Keep completion and copy sounds, attention notifications and the finished-work border the same on your computers. Off by default.
- **Keybindings** `syncKeybindings` (boolean, default false): Keep keyboard shortcuts the same on your computers of the same system (a Mac with a Mac, Windows with Windows). Off by default.
- **Coordinator** `syncCoordinator` (boolean, default false): Keep coordinator settings and your edited playbooks (the one for all projects and each project's own, matched by repository) the same on your computers. Off by default.
### Your computers

- **Computers that sync** `syncComputerList` (Settings UI row without a settings key; use `ghostex settings open`): Every computer connected to this one (Remote machines, Easy Connect, Tailscale) joins. Remove one to stop syncing with it; Add back lets it sync again.
### Changed on two computers

- **Recent changes** `syncChangeNotes` (Settings UI row without a settings key; use `ghostex settings open`): When two computers changed the same thing while apart, the later change wins on both. Undo puts the other one back everywhere.
## Secrets (tab `secrets`)

### Secret providers

- **1Password accounts** `secretProviders` (Settings UI row without a settings key; use `ghostex settings open`): The 1Password accounts Ghostex reads keys and tokens from, so you can paste an op://vault/item/field reference instead of the key itself. Needs the 1Password CLI (op) with "Integrate with 1Password CLI" turned on in 1Password. Ghostex keeps only the account name; 1Password may ask you to unlock when a key is read.
### Check a reference

- **Check a 1Password reference** `secretReferenceCheck` (Settings UI row without a settings key; use `ghostex settings open`): Reads an op://vault/item/field reference once to see that it works. Ghostex says only whether it could read it and never shows the value.
### Secrets agents ask for

- **Private secret requests** `secretRequests` (Settings UI row without a settings key; use `ghostex settings open`): When an agent needs a password, API key or token, it asks in a private card above the chat box instead of in the chat. What you type goes to a private file only that agent's commands can read, deleted after 24 hours; it never appears in the chat or reaches the model. With a 1Password account added, you can answer with an op:// reference instead.
## Workspaces (tab `workspaces`)

### Workspaces

- **Workspace name** `workspaceName` (Settings UI row without a settings key; use `ghostex settings open`): The name and letter shown on the workspace button left of your Spaces.
- **Workspace color** `workspaceColor` (Settings UI row without a settings key; use `ghostex settings open`): The color of the workspace button.
- **Work or Personal** `workspaceKind` (Settings UI row without a settings key; use `ghostex settings open`): A Work workspace can share a team backend with your team (requests from Slack, the team's Linear key); a Personal one is just yours.
- **Primary tracker** `workspaceTracker` (Settings UI row without a settings key; use `ghostex settings open`): Linear tickets & projects, or GitHub issues & projects: what Create ticket, the Issues view, Link to and Slack use. Shows the command that lets Ghostex read GitHub Projects when it can't yet.
- **Linear API key** `workspaceLinearApiKey` (Settings UI row without a settings key; use `ghostex settings open`): The Linear key this workspace's projects use, unless a project sets its own.
- **Claude account** `workspaceClaudeAccount` (Settings UI row without a settings key; use `ghostex settings open`): Which of your Claude accounts agents in this workspace's projects use.
- **Browser sign-ins** `workspaceBrowserSignins` (Settings UI row without a settings key; use `ghostex settings open`): Each workspace's Browser keeps its own cookies; sign out of every site here.
- **Site permissions** `workspaceSitePermissions` (Settings UI row without a settings key; use `ghostex settings open`): Forget your Allow and Don't Allow answers to sites in a workspace's Browser, such as a site connecting to apps on this computer.
- **New workspace** `newWorkspace` (Settings UI row without a settings key; use `ghostex settings open`): Add a workspace, for example one per company you work for.
### Team

- **Team (Convex)** `teamConvex` (Settings UI row without a settings key; use `ghostex settings open`): Join your team's Convex project with an invite link, copy an invite link for a teammate, or leave the team.
- **Set up a new team** `teamSetup` (Settings UI row without a settings key; use `ghostex settings open`): Deploy Ghostex's functions to your own Convex project with ghostex team deploy in a terminal.
- **Slack app manifest** `slackAppManifest` (Settings UI row without a settings key; use `ghostex settings open`): Copy the manifest that creates your team's Slack app.
- **Slack bot token and signing secret** `slackSecrets` (Settings UI row without a settings key; use `ghostex settings open`): Stored in your team's Convex project with ghostex team slack-connect.
- **Your Slack user** `slackUser` (Settings UI row without a settings key; use `ghostex settings open`): Your Slack member ID and the one-time code from Ghostex's private Slack reply, so @Ghostex commands you send in Slack reach this computer.
- **Linear for the team** `teamLinearKey` (Settings UI row without a settings key; use `ghostex settings open`): The team-wide Linear key Slack commands use to find and create tickets. Only the team's owners set or remove it; tickets created with it show the key's owner as the creator in Linear.
- **Create my Slack tickets with my own Linear key** `teamOwnLinearKey` (Settings UI row without a settings key; use `ghostex settings open`): Tickets you request from Slack are created with this workspace's Linear key, so Linear shows you as their creator.
### Team flow

- **Working channel** `teamWorkingChannel` (Settings UI row without a settings key; use `ghostex settings open`): The Slack channel where each ticket gets its one working thread.
- **Watch-only channels** `teamWatchOnlyChannels` (Settings UI row without a settings key; use `ghostex settings open`): Slack channels where a request is forwarded to the ticket's working thread and only gets a 👀.
- **Repos for new work** `teamChannelRepos` (Settings UI row without a settings key; use `ghostex settings open`): Which repo and Linear team new work from each Slack channel goes to.
- **Where new work runs** `teamDefaultRunPlace` (Settings UI row without a settings key; use `ghostex settings open`): Cloud or this computer, for @Ghostex in Slack without cloud or local.
- **Never work without a ticket** `teamNeverWithoutTicket` (Settings UI row without a settings key; use `ghostex settings open`): Ghostex finds the ticket in the thread or creates one in Linear before any session starts. Always on.
- **Team instructions** `teamInstructions` (Settings UI row without a settings key; use `ghostex settings open`): Your team's rules, added to every session Ghostex starts from Slack.
- **Team-flow steps** `teamFlowSteps` (Settings UI row without a settings key; use `ghostex settings open`): The steps each ticket shows in the Issues view, shared by the whole team: reorder, rename, remove or add them, or reset to the default. Only the team's owners can change them.
## Connectors (tab `connectors`)

### Composio

- **Composio sign-in** `composioSignIn` (Settings UI row without a settings key; use `ghostex settings open`): Sign a workspace in to Composio once in your browser, or sign it out.
- **Composio apps** `composioApps` (Settings UI row without a settings key; use `ghostex settings open`): Connect Gmail, Google Calendar, Slack, Notion, GitHub, Linear and more apps for a workspace's agents.
### Executor

- **Executor** `executorEnabled` (Settings UI row without a settings key; use `ghostex settings open`): Turn on Executor for a workspace; Ghostex downloads it the first time and runs it on this computer.
- **Executor apps** `executorApps` (Settings UI row without a settings key; use `ghostex settings open`): Add apps from Executor's catalog or any remote MCP server, sign them in and remove them.
- **Sign-in callback address** `executorCallbackUrl` (Settings UI row without a settings key; use `ghostex settings open`): The address to give an app's developer console when it needs your own sign-in app (OAuth client).
### When agents change something

- **Ask, Allow or Never** `connectorRulesDefault` (Settings UI row without a settings key; use `ghostex settings open`): What a workspace does before an agent sends, posts, creates, changes or deletes something through a connector: ask on a card, allow it, or never run it.
- **Rules for one tool** `connectorRulesTools` (Settings UI row without a settings key; use `ghostex settings open`): The tools set to always allow or never run, for example after Always allow on a card.
### Command-line sign-ins

- **GitHub CLI and Google Workspace CLI** `connectorCliSignIns` (Settings UI row without a settings key; use `ghostex settings open`): Each workspace's own gh and gws sign-in, which agents started there use.
## Voice (tab `voiceAgent`)

### Dictate

- **Engine** `dictateEngine` (Settings UI row without a settings key; use `ghostex settings open`): Which service turns your recording into text: a local model on this computer (no key, works offline), OpenAI or xAI. A new install picks your saved key (xAI, then OpenAI) and the local model when there is no key; after that it stays on what you pick. Each computer has its own engine, and the phone changes it per computer.
- **Local models** `dictateModels` (Settings UI row without a settings key; use `ghostex settings open`): Models that run on this computer with no key and work offline: Parakeet TDT 0.6B v3 (fastest, English and 24 European languages), Whisper large-v3-turbo (99 languages) and Whisper base (small and quick). Download, cancel or remove each one; the one you pick transcribes. Stored in gxserver's data folder.
- **Language** `dictateLanguage` (Settings UI row without a settings key; use `ghostex settings open`): Auto works for most people. Pick one when short phrases come out in the wrong language.
- **Hotkey** `dictateHotkey` (Settings UI row without a settings key; use `ghostex settings open`): Dictate into the chat box you are in. Change it in Hotkeys.
- **Hotkey mode** `dictateHotkeyMode` (one of auto | toggle | hold; default auto): Auto: tap to start and tap again to stop, or hold for 300 ms or more and it stops when you let go. Toggle: every press starts or stops. Hold: it records only while you hold the keys. Escape cancels. Option labels: auto = Auto, toggle = Toggle, hold = Hold.
- **Microphone** `dictateMicrophone` (text, default (empty)): The microphone this computer records Dictate from. System default follows the input device chosen in your sound settings.
### Clean-up

- **Dictionary** `dictateDictionary` (Settings UI row without a settings key; use `ghostex settings open`): Names and terms it should expect. An alias fixes a word it keeps mishearing ("GX server" becomes gxserver). Your project names are added on their own.
- **Remove filler words** `dictateRemoveFillers` (Settings UI row without a settings key; use `ghostex settings open`): Drops "um", "uh" and other hesitation sounds.
- **Insert with spacing** `dictateInsertSpacing` (boolean, default true): Adds a space before or after the text when the characters next to the caret need one.
- **AI polish** `dictatePolish` (Settings UI row without a settings key; use `ghostex settings open`): Claude Sonnet 5.5 fixes punctuation and keeps what you meant when you corrected yourself ("no, I mean…"), through Claude Code on the computer that transcribes. The chat box shows Polishing with a Skip button; if it fails, the text goes in unpolished.
### Voice agent

- **Voice provider** `voiceAgentProvider` (one of xai | openai; default xai): Which realtime voice model you talk to: xAI Grok Voice or OpenAI GPT Realtime. Both are billed by the provider while a conversation is open. It doesn't follow Dictate's engine: Dictate can stay local while calls use xAI or OpenAI. Option labels: xai = xAI Grok Voice, openai = OpenAI GPT Realtime.
- **Grok voice** `voiceAgentXaiVoice` (one of eve | ara | rex | sal | leo | altair | atlas | aurora | carina | castor | celeste | cosmo | helios | helix | iris | kepler | liora | lumen | luna | lux | naksh | orion | perseus | rigel | sirius | ursa | zagan | zenith; default eve): The voice Grok Voice speaks with. Option labels: eve = Eve, ara = Ara, rex = Rex, sal = Sal, leo = Leo, altair = Altair, atlas = Atlas, aurora = Aurora, carina = Carina, castor = Castor, celeste = Celeste, cosmo = Cosmo, helios = Helios, helix = Helix, iris = Iris, kepler = Kepler, liora = Liora, lumen = Lumen, luna = Luna, lux = Lux, naksh = Naksh, orion = Orion, perseus = Perseus, rigel = Rigel, sirius = Sirius, ursa = Ursa, zagan = Zagan, zenith = Zenith.
- **OpenAI voice** `voiceAgentOpenaiVoice` (one of marin | cedar | alloy | ash | ballad | coral | echo | sage | shimmer | verse; default marin): The voice GPT Realtime speaks with. Marin and Cedar sound the most natural. Option labels: marin = Marin, cedar = Cedar, alloy = Alloy, ash = Ash, ballad = Ballad, coral = Coral, echo = Echo, sage = Sage, shimmer = Shimmer, verse = Verse.
- **Speaking speed** `voiceAgentSpeed` (one of 1 | 1.2 | 1.4 | 1.6 | 1.8 | 2; default 1): How fast the voice agent talks, from normal speed to twice as fast. The voice keeps its pitch, and the speed menu next to the voice in the voice panel changes it too, even mid-sentence. Option labels: 1 = 1×, 1.2 = 1.2×, 1.4 = 1.4×, 1.6 = 1.6×, 1.8 = 1.8×, 2 = 2×.
- **Call mode** `voiceAgentCallMode` (one of regular | pushToTalk; default regular): Regular calls listen hands-free; on Grok they're billed for the whole time the call is connected, quiet and muted time included (about $0.08 a minute). Push-to-talk calls listen only while you hold the talk button next to Mute (or Space, or the Hold to Talk hotkey); on Grok you pay only for the audio you send and the agent's replies. In a muted Regular call, holding it unmutes you for as long as you hold. GPT Realtime bills only audio in both modes. A change applies to your next call; the gear in the voice panel changes it too. Option labels: regular = Regular, pushToTalk = Push-to-talk.
### Memory

- **Last conversation** `voiceAgentMemory` (Settings UI row without a settings key; use `ghostex settings open`): A short summary of your last voice conversation, kept on this computer until the next conversation replaces it. Press Continue in the voice panel, or say "pick up where we left off", to carry on from it. Forget deletes it.
### API keys

- **xAI API key** `voiceAgentXaiKey` (Settings UI row without a settings key; use `ghostex settings open`): Used by the voice agent on Grok Voice, and by Dictate when its engine is xAI. Kept encrypted on this computer; your phone uses it through this computer and never stores it. With a 1Password account added in Settings > Secrets, paste an op://vault/item/field reference instead and the key is read from 1Password each time.
- **OpenAI API key** `voiceAgentOpenaiKey` (Settings UI row without a settings key; use `ghostex settings open`): Used by the voice agent on GPT Realtime, and by Dictate when its engine is OpenAI. Kept encrypted on this computer and never shown again after you save it. With a 1Password account added in Settings > Secrets, paste an op://vault/item/field reference instead.
### Dictation history

- **Dictation history** `voiceAgentDictationHistory` (Settings UI row without a settings key; use `ghostex settings open`): Every recording you made with the Dictate microphone, newest first, with its text and the engine that made it. Play, download or delete a recording, copy its text, recover one you cancelled, or transcribe one that failed (the text is copied to your clipboard too). Recordings stay on this computer until you delete them.
