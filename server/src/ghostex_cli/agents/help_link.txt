Lead links: sessions that report to a lead. Use them only when the user asked
for sessions to report to you; read `ghostex agents guide leads` first.

USAGE
  ghostex agents create <agent-id> --lead <session-ref|self> [--model <m>] [--effort <e>]
                       [--role <line>] [--task <text>] ...
  ghostex agents link <session-ref> --lead <session-ref|self> [--role <line>]
  ghostex agents links [--all] [--json]
  ghostex agents unlink <session-ref>
  ghostex agents unlink --all [--lead <session-ref>]
  ghostex agents role set "<line>" [--session <ref>] | show | clear  (see agents role --help)

  A linked session's final message reaches its lead at the end of each turn
  the lead started with a message (ghostex agents send, or --queue; a
  --with-next note starts no turn, so it is not reported), and the lead hears
  when it waits for an answer, goes quiet for 8 minutes or is closed during
  such a turn. Turns the user starts in it are not forwarded.

  --lead self is the calling session; a session can only link others to
  itself. From the user's own terminal, --lead takes any session ref.
  links lists the sessions linked to you and to your sub-leads, each with its
  chain of leads, and whom you report to (--all: every link on this computer).
  unlink --all ends every link to you (from your own terminal, to the lead
  --lead names); unlinking a sub-lead keeps its own links. Links go at most
  two levels deep (a lead, its sub-leads, their sessions; never a loop), and
  a lead hears only the turns it started in its own linked sessions (a message
  to a sub-lead's session is not reported to anyone). All sessions must be on this
  computer; a coordinator or a coordinator's thread can't be linked or lead.
