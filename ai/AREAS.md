# CDXC areas

The canonical list of `CDXC:<Area>` tags. Every CDXC comment in `apps/`,
`packages/`, `server/`, `tooling/`, and the edited parts of `.dependencies/`
uses one of these names. The rules for writing CDXC comments are in
`AGENTS.md` ("CDXC comments: why the code exists, and what the user decided").

How to use this file:

- **Before writing a tag, pick the row whose "Covers" text describes the
  feature your change belongs to.** Use it even when your change is a
  sub-feature of it; put the specific detail in the comment text, not in the
  tag. `rg 'CDXC:<Area>'` then finds every related comment.
- **Do not add an area for one change.** Add a row only when no row covers the
  feature at all, the feature is user-visible or a cross-crate contract, and
  several comments will share it. Add the row in the same commit as the first
  comment and say so in your report. Keep the row's "Covers" sentence short
  and scope-defining.
- **Never create a variant of an existing area** (`SidebarSessions` next to
  `Sessions`, `CommandPaneActions` next to `CommandPane`) and never derive a
  name from a file, struct, task, or host surface (`GPUI…`, `React…`).
- Areas are PascalCase feature or contract names. `Mobile` and
  `PlatformSupport` are the deliberate exceptions: they record constraints a
  platform imposes, not features. Anything a platform shares with the others
  goes to the feature area.
- If a row's scope stops matching the code, edit the row. Renaming or merging
  an area is a repo-wide mechanical pass; do it only in a quiet worktree and
  record the mapping under `docs/`.

History: 1,331 tags were folded into these areas on 2026-09-03. The full
old-to-new mapping is `docs/2026-09-03/cdxc-area-mapping.tsv`; the "Formerly"
column lists a few of the old names so agents working from older notes can
find the new home.
