PLN / Guardrails

Rules that prevent false progress

These constraints follow directly from the code audit and Ghostex’s repository policies.

GRD-01

No cosmetic-only rewrite

Visual polish may ship early, but semantic activity UI must be backed by structured event data.

GRD-02

No fake capabilities

Do not show model, fork, permission, or steering actions that the selected provider cannot honor.

GRD-03

No static catalog as truth

Use live discovery and verification state; curated entries are presentation metadata.

GRD-04

No transcript fallback maze

Where a structured protocol exists, start in the correct protocol mode instead of trying a weaker path first.

GRD-05

No overlapping input surfaces

Use normal layout, existing panes, or native child surfaces for secondary chat and menus.

GRD-06

Preserve shared hosts

Desktop and web should continue sharing chat components through explicit host capabilities.
