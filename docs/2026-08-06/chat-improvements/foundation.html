FND · Architecture

Give the interface better facts.

Ghostex currently compresses provider activity into five roles and four block types. A richer shared event contract is the prerequisite for trustworthy streaming, accurate tool correlation, semantic activity cards, and scalable provider support.

Core rule

Provider-specific parsing belongs at the gxserver boundary. UI components should render one normalized projection.

On this page Event contract Timeline projection Streaming Provider registry Host capabilities
FND-01 · P0

Provider-neutral event contract

Extend the shared chat protocol with enough identity and structure to represent modern coding-agent work without flattening it into prose.

FND-01A

Stable identity

Add turn, message, tool-call, result, and parent IDs. Pair results by identity rather than FIFO order.

FND-01B

Lifecycle

Represent queued, running, completed, failed, denied, interrupted, and stale states with timestamps and duration.

FND-01C

Work kinds

Commands, file changes, web research, delegations, plans, workflows, questions, approvals, and artifacts.

FND-01D

Usage

Context usage, token counts, compaction, model fallback, and execution-tier changes.

FND-01E

Compatibility

Add optional fields first and version the wire contract so older daemons remain understandable during migration.

WHY

Today, tool results do not carry a call identity. Concurrent or out-of-order work cannot be paired reliably, and provider-specific progress is discarded.

Ghostex: shared/session-chat.ts · sidebar/chat/session-chat-tool-fold.ts · gxserver-rs/src/session_chat.rs

FND-02 · P0

FND-02A

Active frontier stays open

Pending, failed, interrupted, approval-blocked, and newest work remain visible. Old successful detail can recede.

FND-02B

Grouping is reversible

A summary never destroys its source rows. Users can expand a step to inspect exact commands, patches, or tool data.

Carry assistant and reasoning deltas with stable turn IDs, while retaining the transcript as the final authority.

Describe what each provider can do instead of branching on agent IDs throughout TypeScript, Rust, commands, and UI.

FND-05 · P1

Host capability injection

Keep one shared React chat surface while desktop and web hosts declare link routing, file access, native selection, and session actions.

FND-05A

Explicit host features

Render actions only when the host supplies a verified capability. Avoid hidden desktop-only branches in shared components.

FND-05B

Portable semantic rows

Timeline rows remain platform-neutral; opening a file, URL, terminal, or child pane is delegated to the host.
